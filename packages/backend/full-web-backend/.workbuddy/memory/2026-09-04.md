## 项目整体结构梳理

`full-web-backend/` 是一个**多版本实验容器**,并非单一连贯产品,根目录无 `package.json` / `README.md`,由 7 个相对独立的子项目组成:

| 子项目 | 形态 | 技术栈 | 业务定位 | 状态 |
|---|---|---|---|---|
| `V0-atctiku/` | Express + Sequelize/MySQL | 题库分页查改、错题标记、CSV 导入导出 | 集中式路由,`app.listen(3103)` | 已完成可运行 |
| `V1-api/` | Express + Sequelize/MySQL | 工程/人员管理(todos/worker/bill/company/plan/salary) | 分层 controller/route/model,**无 listen 入口** | 不可直接启动 |
| `V2-api/` | Express + MySQL + ws | 公司综合业务(名片/考勤/报价单/表单) | 路由导出函数,被引用模块 | 不可直接启动 |
| `V3-api/` | Express + MySQL + ws + multer | V2 超集,加 calendar/document/product、WebSocket 推送、errorHandler/throttle | `app.listen(3100)`,**动态扫描 modules 目录**注册路由 | 已完成可运行 |
| `v4-tower-duty/` | Express + **sqlite3** + JWT + socket.io | **空管塔台值班/交接班考勤系统**(席位 11 类、工时统计、HR 工时汇总) | 端口 3205,纯后端,**无前端 UI** | 后端就绪,前端待建 |
| `V5-dispatch/` | Express + **PostgreSQL** + pg + dayjs | **航班调度系统**(航班/检查单/手动航班/生鲜货物) | 端口 5183,完整 5 表结构,4 个 .http 测试 | 框架完成,待联调 |
| `public/`、`uploads/` | 静态资源 + 用户上传(头像/PDF/CSV) | — | — | — |

### 关键观察

1. **V0~V3 是历史迭代归档**:MySQL + 老版 Express,代码已稳定但非主战场;V3 是最规整的(动态路由注册)
2. **V4 与 V5 是当前主战场**,但技术栈不同:
   - **V4 tower-duty**:SQLite + JWT + 纯后端(端口 3205,与记忆中 5183 不一致 — 用户提到的 5173/5183 应该是 V5 的端口,记忆里 V5 是 5183,实测 V5 `.env` 端口就是 5183)
   - **V5 dispatch**:PostgreSQL + 完整前后端分离(后端 5183)
3. V4 实际连接 **SQLite(`src/test.db`、`src/user-face.db`)**,不是 PostgreSQL;`.env` 里残留的 `prisma+postgres://` 是模板,代码无 pg 引用
4. V5 的 `data/` 内置 7 个检查单模板 JSON + `schema.sql`,自带 initDb 幂等建库
5. `uploads/` 下的 4 个哈希目录名是用户上传文件落地目录

## v4-tower-duty 深度分析(9/4 下午,端口 3205)

**身份**:浙江空管塔台值班/交接班考勤系统后端 `zhec-tower-server-v3`,纯后端,**无前端 UI**,express@4 + sqlite3,`dev = nodemon server.js`,`main=index.js`(文件不存在,靠 dev 脚本跑 server.js)。

**双 SQLite 库**:
- `src/test.db` → DutyDb:表 duty(1.2万+原始行,实查 22242 条)、prepare、photo、duty_audit_log(触发器自动审计)、hr_duty_summary;主表 duty 结构无建表语句(靠预先建好的 db 文件),代码只建 trigger(prevent_insert_if_unfinished / log_all_duty_updates / log_all_duty_deletes)与两个辅助表
- `src/user-face.db` → UserDb:表 user(40人)、position(17)、duty_type 概念、images、user_team

**分层齐全**:routes(6 个 route)/ controllers(6) / services(9) / middlewares(6) / config / utils,带 CRUD 注释;utils/util/see.js 实际是 SSE(initSSE/sendEvent/startHeartbeat),app.js 引入但**从未启用**,dutyController 中 sendEvent 全被注释。

**领域规则**(config/Const.js):席位 = 东/西塔台+东/西地面+放行+进近高低扇+流控/领班+综合协调+航班/生产调度席;工时规则 MAX_CONSECUTIVE 10h / 24h 累计 10h / 周 40h / 席位连续 6h;CalcRule 按席位类别聚合统计。clipDutyRow 做"角色段 + 夜班段切割",夜班=18:00→次日08:30。statisticsService.*:NightCount(夜班频次/段数)、PositionSummary(席位主/副班时长)、CalcuUserStats(按 CalcRule 规则汇总)、CheckDuration(24h/7d 滑动窗口超时合规检查,checkV3 为算法核心)。

**Excel 排班**:public/ExcelDutyFiles/{年}-{月}.xlsm,sheet 名=用户名,第2行表头、第3行起数据;uploadService 用 multer + xlsx 读写,**暂只读**,写仅存文件。

**发现的问题**:
1. **鉴权中间件未接线**:middlewares/auth.js 有 authenticateToken/optionalAuth/requireAdmin,但 router.js 一条都没挂 → 所有业务接口实际上无鉴权(登录只有 login/refresh token 逻辑)
2. **登录疑似不可用**:user 表无 password 列、userService ALLOWED_COLUMNS 也无 password,而 authController 用 username+password 明文比对 → 除非预置了别的机制,否则 login 恒失败;.http 测试却写 /api/login(与真实 /api/auth/login 也不符)
3. **positionService.create 引用了未定义变量 `base.db`** → 建 position 会 ReferenceError
4. checkRoleMiddleware.checkDutyMiddleware 算了 hasRoleTypePermission/hasDutyTypePermission 却未用其拦截,直接 next()
5. 注释掉的 HTTPS / Prisma / 旧 controller 代码残骸多;.env 是 Prisma 模板残留(DATABASE_URL prisma+postgres 无实际作用,代码不读 dotenv)
6. app.js 里 `/api`, `/`, `/public`, `/images` 四重静态目录全指 public,冗余

**状态判断**:核心业务(执勤 CRUD+审计+夜班/席位/合规统计+Excel 排班)已实现且带真实历史数据(22242 条 duty),但"后端就绪,前端待建";认证/部分中间件属半成品,疑与真实使用方(前端/另一套入口)分头开发后未合并。

## 夜班统计 V2 修复(9/4 晚)

创建 `controllers/statisticsControllerV2.js` + `services/statisticsService.NightCountV2.js`,修复夜班统计两个 bug:
1. **月份错位**:旧 `getStatisticsTimeRange` 用 `dayjs().month(m)`(0 基)而接口传自然月 → 传 5 实际统计 6 月;V2 用 `month(m-1)` 按自然月解析
2. **窗口边界错**:夜班日界应为 08:30(班 d 日18:00→d+1日08:30),旧窗口 当月1日00:00→下月1日00:00 会漏掉月末凌晨段、错含月初记录;V2 窗口改为「当月01日 08:30:00 → 次月01日 08:30:00」

V2 算法:先 `queryDuty` 拉窗口内记录 → 按 userId 分组(支持 userId 单查)→ 每条记录从「开始日-1」循环到「结束日」判定命中夜班日 → 三段(18-21/21-24/+1天00-0830)计重叠小时 → 任一子段>0.7h 记 1 次夜班、每子段≥0.75h 计 1 段(口径沿用 V1)→ summary 汇总 + 移除空日期。
Controller V2 允许参数 `year/month/filter/userId`(userId 需入白名单否则传参即 400)。
已用真实库核验:2026-05 共 38 用户;userId=4 → 夜班次数 15 / 段数 30,与独立 SQL 核验一致。注:新增文件未接路由,需自行改 `statistics.route.js` 引 V2。
