# V5-dispatch 后端部署到阿里云服务器（完整步骤）

> 目标：把 `flight_dispatch` 后端（Express + PostgreSQL）部署到已装有 PostgreSQL 的阿里云服务器。
> 重点：**复用服务器上已有的 express 等公共包，不重复装一大堆依赖，节省磁盘空间。**

---

## 〇、先说清楚"复用 express 包"的正确姿势（重要）

你的项目是 **ESM 项目**（`package.json` 里 `"type": "module"`，代码用 `import` 语法）。

- ❌ **`NODE_PATH` 全局复用方案对 ESM 无效**：`NODE_PATH` 只对 CommonJS 的 `require()` 生效，Node 的 ESM（`import`）**不读取 NODE_PATH**。所以"全局装 express，然后设 NODE_PATH"这条路走不通。
- ✅ **正确方案：pnpm 全局 store（内容寻址存储）**。pnpm 把所有包的真实文件存在一个全局 store（磁盘只存一份），每个项目里的 `node_modules` 只是**符号链接**指向 store。这样：
  - express、pg、cors 等无论多少个项目用，**磁盘上只有一份**；
  - 新项目 `pnpm install` 时，如果包已在 store 中，秒装完成、几乎不占新空间。

你本机项目本来就是 pnpm workspace（`node_modules` 里都是软链），服务器上同样用 pnpm 就能天然共享。

## 一、服务器环境准备（只需做一次）

```bash
# 1. 确认 Node.js 版本（要求 ≥ 18，推荐 20/22 LTS）
node -v

# 如果没有或版本太低：
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt-get install -y nodejs

# 2. 安装 pnpm（全局，只装一次，所有项目共享）
npm install -g pnpm

# 3. 安装 PM2 进程守护（全局，只装一次）
npm install -g pm2

# 4. 确认 PostgreSQL 已装并运行
sudo systemctl status postgresql   # 或 service postgresql status
```

---

## 二、上传后端代码（不含 node_modules）

只需上传以下内容到服务器，例如 `/opt/v5-dispatch/`：

```
V5-dispatch/
├── package.json          # 依赖清单（6 个包）
├── .env                  # 配置（按服务器改）
├── src/                  # 全部后端源码
└── data/
    └── checklists/       # 检查单模板 JSON（必须带上）
        ├── cargo-checklist.json
        └── passenger-checklist.json
```

```bash
# 本地打包（在 V5-dispatch 目录）：
tar -czf v5-dispatch.tar.gz package.json .env src data

# 上传到服务器（任选）：
scp v5-dispatch.tar.gz root@服务器IP:/opt/
# 或宝塔面板/阿里云文件管理上传

# 服务器上解压：
cd /opt
mkdir -p v5-dispatch && tar -xzf v5-dispatch.tar.gz -C v5-dispatch
```

> ⚠️ 不要上传 node_modules（本机是 pnpm 软链，直接拷没用），服务器上用 pnpm 重新装，秒装且共享 store。

## 三、导入数据库（用之前的导出包）

之前已把 `flight_dispatch.sql` 和免密脚本放在 `资料/` 目录：

```bash
# 上传资料目录里的 flight_dispatch.sql（免密脚本可选）
scp flight_dispatch.sql root@服务器IP:/root/

# 服务器上执行（先给 postgres 设个密码，或直接用免密方式）
cd /root
sudo -u postgres psql -c "ALTER USER postgres WITH PASSWORD '你的密码';"
PGCLIENTENCODING=UTF8 sudo -u postgres psql -d postgres -c "CREATE DATABASE flight_dispatch ENCODING 'UTF8';"
PGCLIENTENCODING=UTF8 sudo -u postgres psql -d flight_dispatch < flight_dispatch.sql

# 验证行数
sudo -u postgres psql -d flight_dispatch -c "SELECT 'flights' t,count(*) FROM flights UNION ALL SELECT 'fips',count(*) FROM fips UNION ALL SELECT 'checklist_records',count(*) FROM checklist_records;"
```

## 四、配置 .env（改 3 个地方）

```bash
cd /opt/v5-dispatch
vim .env
```

```ini
# Server
PORT=5183
HOST=0.0.0.0

# PostgreSQL —— 改成服务器的密码
PG_HOST=127.0.0.1
PG_PORT=5432
PG_USER=postgres
PG_PASSWORD=你的密码
PG_DATABASE=flight_dispatch

# CORS —— 改成线上前端地址（重要！）
CORS_ORIGIN=https://你的前端域名,http://你的前端IP:5173
```

## 五、安装依赖（复用全局 store，不重复占空间）

```bash
cd /opt/v5-dispatch
pnpm install --prod
```

- express、cors、pg 等如果服务器上其他项目已用过，**pnpm 直接复用 store 里的文件**，仅生成软链；
- 如果还想更彻底（完全不落地到项目目录，只留软链），用 `pnpm install --prod --shamefully-hoist=false`（默认即是软链模式）。

---

## 六、启动 + 进程守护（PM2）

```bash
cd /opt/v5-dispatch
pm2 start src/server.js --name v5-dispatch
pm2 save                    # 保存进程列表
pm2 startup                 # 开机自启（按提示执行输出的命令）

# 常用命令
pm2 status                  # 查看状态
pm2 logs v5-dispatch        # 看日志
pm2 restart v5-dispatch     # 重启
```

## 七、放行端口 + 验证

- 入方向放行 **5183** 端口（或只对前端服务器 IP 放行，更安全）


## 八、（可选）Nginx 反向代理

如果不想暴露 5183 端口，可以让 Nginx 把 `/api` 转发到后端：

```nginx
# /etc/nginx/conf.d/v5-dispatch.conf
server {
    listen 80;
    server_name api.你的域名.com;

    location /api/ {
        proxy_pass http://127.0.0.1:5183;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

```bash
sudo nginx -t && sudo systemctl reload nginx
```

## 九、前端怎么连后端

前端 `src/api/index.js` 读取 `VITE_API_BASE`（默认 `http://localhost:5183/api`）。
部署时给前端项目配置环境变量：

```bash
# 前端项目根目录建 .env.production
VITE_API_BASE=https://api.你的域名.com/api
# 或 VITE_API_BASE=http://服务器IP:5183/api
```

然后重新构建前端 `npm run build`，把 `dist/` 部署到 Nginx/OSS。

## 附录：三种"复用依赖"方案对比

| 方案 | 是否可行 | 说明 |
|---|---|---|
| **pnpm 全局 store（推荐）** | ✅ | 包文件全局只存一份，各项目软链引用；本机已是 pnpm 项目，零成本切换 |
| NODE_PATH 指向全局 node_modules | ❌ | 只对 CommonJS 生效，本项目是 ESM（import），不读取 NODE_PATH |
| 手动建共享 node_modules + symlink | ⚠️ | 可行但繁琐，pnpm 已内置此能力，无需手动 |

> 结论：**服务器上统一用 pnpm 装依赖**，所有 Node 项目共享一个 store，express 等公共包磁盘上只有一份，彻底解决"一个程序装一大堆包"的问题。
