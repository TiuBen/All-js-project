### 3. 三栏不满宽修复（components/ResizableColumns.jsx 重写）
- 旧实现两个缺陷：
  1. 固定 px 宽度；容器变宽时用「旧 widths / 新 clientWidth」求比例，比例和 ≠ 1 → 列宽总和停留在旧值，右侧留白；ResizeObserver 也掩盖不住。
  2. `columns` 传入的是 `panels.includes(x) && {...}`，未选中项为 `false` 仍被算进 `n = columns.length` → 多渲染一块空列（如无辅助节点时）。
- 新实现：
  - 宽度改为 **flex 比例**（`flexGrow: ratio` + `flexBasis: 0` + `flexShrink: 1`），由浏览器按比例填满容器，首帧/变宽/缩放均不留白。
  - `columns.filter(Boolean)` 先过滤 falsy 项，列数与实际渲染一致；列数变化时重置为均分。
  - 拖拽改为「起点像素 → 比例」换算，夹紧逻辑保持两列宽度和不变；`ratiosRef` 避免拖拽回调闭包旧值。
- 校验：`npx esbuild src/pages/ChecklistPage/index.jsx --bundle --jsx=automatic` 零报错；5173 dev server 200（HMR 生效）。

## 视频监管重点：id 唯一化 + 前端内联 + 逐项渲染（性能优化）

### 1. item id 改写为全局唯一 vCheckId
- 起因：原 `items[].id` 在**每个组内**从 1 开始（跨组重复），无法作为唯一 key。
- 改写结果（跨文件连续编号，全局唯一，0 重复）：
  - `客运航班视频监管重点.json`：3 组 38 项 → `vCheckId1 ~ vCheckId38`
  - `货运航班视频监管重点.json`：4 组 44 项 → `vCheckId39 ~ vCheckId82`
- 组的 `id`（1/2/3/4）保持不变，只改 item。`客运始发航班.json` 的 `videoSupervision` 实为空数组，无可改项（已核实：7 个模板文件的节点 videoSupervision **全为空**）。

### 2. 视频监管数据内联到前端（不再请求后端）
- 新增 `src/pages/ChecklistPage/videoFocus/`：

  - `index.js`：`resolveVideoFocus(category)` 本地解析 + `ALL_VIDEO_CHECK_IDS`（82 个）
