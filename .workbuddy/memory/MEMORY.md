ADD COLUMN uuid`，任何一次进程在旧代码上启动都会在**最后一列**重新长出 `uuid`（值是全新随机值、与 id 无关），库变成「id 已是 uuid + 又一个假 uuid 列」的混合态。→ `schema.js` 新增 `dropRedundantUuidColumns()` 并**并进 initDb() 做幂等收敛**（`MERGED_UUID_TABLES = ['fips','manual_fips','ecyilang']`）。**DB 里凡是历史迁移产物，都要在 initDb 里有对应的收敛步骤**，别只写在一次性脚本里（⚠️ `schema.js` 已于 2026-10-03 下午移入 `db_seed/`，该收敛逻辑随之停用）

- **⚠️ PG 占位符只能有一种推断类型（2026-10-03 连踩两处）**：同一个 `$n` 出现在两种不同要求的上下文里，PG 直接报 `inconsistent types deduced for parameter $1`（**即使两个类型之间存在隐式转换也不行**，varchar vs text 就够炸）。两个实例：①`specialService` 的 `VALUES ($1,$2,$3, resolve_flight_uuid($1,$2))` —— `$1` 被 `callsign` 列(varchar) 与函数形参(text) 双重定型 → 改成**独立占位符 `$4` 传同一个值**（`createRow`/`upsertByKey` 两处）；②`syncChecklistUuid` 的 `WHERE id = base_flight_uuid($1)` —— id 变 uuid 后必须写成 **`WHERE id = $2::uuid`**，且 `$1`(text, 喂 `base_flight_uuid`) 与 `$2`(uuid, 比主键) **必须是两个占位符**。**表达式之间的类型转换没问题，只有参数是严格的。**
