## 补完「非受控」：输入框与公式上下文

用户复查 `AuxiliaryCheckItem.jsx` 后指出"怎么还是受控组件"——**我把"非受控"理解窄了**：
上一轮只做到"数据不从 props 传"，但输入框仍是 `value` + `onChange`（React 受控输入），
且 `formulaCtx` 还是面板传下来的。这两处都改掉。

### 改动
| 文件 | 改动 |
|---|---|
| `MainCheckItem` / `AuxiliaryCheckItem` | props 收敛到 `{node,index}` / `{aux,anchorId}`；**自算 formulaCtx**（template/flight 从 store 取）；时间输入框改 `defaultValue` + ref |

| `AuxiliaryPanel` | 同上，只渲染 `<AuxiliaryCheckItem aux anchorId />` |

### ⚠️ 非受控输入的要害
`defaultValue` 只在挂载时生效 —— 必须有 ref 同步 effect：
```jsx
useEffect(() => { if (ref.current && ref.current.value !== v) ref.current.value = v }, [v]);
```
否则**公式引擎自动写入的时间、记录/草稿回填都不会显示**。
本项目 aux/main 的 `time` 会被 `TimeFormulaEngine` 自动写入，textarea 的 `note` 会被记录回填 → 全都依赖这条 effect。

## 表单改造成 react-hook-form 形态（用户纠正我第二次）

用户：「你还是理解错了, 我想模仿的是 react hook form 每个 input 之类的 没有什么 onChange」

**我前两轮理解都偏了**：
- 第一次理解成"数据不从 props 传"，只把数据源内部化
- 第二次理解成"React 非受控输入"（defaultValue + ref），但把 `ref` 和 `onChange` **摊在 JSX 里**了

用户要的是 **RHF 的调用形态**：`<input {...register("time")} />` —— 一行展开，
看不见 value、看不见 ref、也看不见手写 onChange。

### 新增 `ChecklistEditor/useRegister.js`
```jsx
const register = useRegister({ time: data.time, note: data.note }, writeField);
<input type="datetime-local" {...register("time", { also: { auto: false } })} />
<textarea {...register("note")} />
```
- 返回 `{ name, ref, defaultValue, onChange }`；`also` = 变更时顺带写入的附加字段
- `ref` 只登记非空元素（避免 detach/attach 的中间空态）
- `useCallback([writeField])` → register 引用稳定，input 不会重挂载
- **保留 values → DOM 的同步 effect**（RHF 里对应 `setValue`/`reset`）：
  本项目 items 会被 TimeFormulaEngine / hydrateFromRecord 偷偷写，没有它那些值不显示
- 三个 Item 的 `writeField` 分别是：`setItemValue(itemKey, …)`（Main/Aux，useCallback 包稳）、`set_vCheckIdN`（Video，store action 本身稳定）

### 验证
`vite build` EXIT 0；5 个面板组基线与 props 版本**逐项一致**；
**14 个 `datetime-local` 全部带 `name="time"`、40 个 `textarea` 全部带 `name="note"`**（证明 register 接管）；
渲染出的 name 只有 `time` / `note`；交互与空模板兜底均正常。
⚠️ SSR 探针看不到事件处理器（React 不序列化 onChange）→ 用 `name=` 属性作为"register 是否接管"的判据。
