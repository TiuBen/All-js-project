## 填写记录页修复 + store 拆分（recordsStore / appStore）

- 需求：填写记录页"选择日期后按检查日期选出对应检查单"功能有问题；要求 records 独立 store；app store 存当前用户 + 所选日期。
- 根因（后端）：`checklistService.listRecords` 按 `flight_date`（航班日期）过滤，与前端日历标记的"检查日期"口径不一致；且手动航班 flight_date 为 NULL 会混入所有日期。另外 PG 会话时区是 Asia/Shanghai，`(timestamptz + interval '8 hours')::date` 会双重转换（多算 8h，如本地 08-30 16:23 检查的记录被归到 08-31）。
- 修复：date/from/to 改为按 `(COALESCE(checked_at, created_at) AT TIME ZONE 'UTC' + interval '8 hours')::date` 过滤（确定性东八区取日，不依赖会话时区/tzdata）。
- 前端结构：
  1. 新建 `store/appStore.js`：useAppStore（persist 'flight-dispatch:app'），存 currentUser（当前用户，空壳待接入）+ 日期（mode/selectedDate/rangeFrom/rangeTo，从旧 useDateStore 迁入）。
  2. 新建 `store/recordsStore.js`：useRecordsStore 管 records/loading/keyword/dayMarkers/refreshKey，动作 fetchRecords（按 appStore 日期拉取）、fetchDayMarkers（全量统计日历红绿数字）、refresh、setKeyword。
  3. `tabsStore.js` 删除 useDateStore；`DateFilterPanel.jsx` 与 `FlightSchedulePage/old.jsx` 的 useDateStore 引用全部改为 useAppStore。
  4. `RecordsPage/index.jsx` 去掉本地 state，改订阅 recordsStore，日期变化/刷新触发 fetchRecords + fetchDayMarkers。
- 校验：esbuild 前端 6 文件 + 后端 1 文件全部通过；接口验证 date=2026-08-31 → id 7,8、date=2026-08-30 → id 6、范围 08-11 → id 1~5，时区跨日场景（id 7/8 flight_date=08-30 但本地检查日 08-31）正确归位。
- 经验：PG timestamptz 按东八区取本地日，务必 `AT TIME ZONE 'UTC' + interval '8 hours'`，不要直接 `+ interval` 后 `::date`（会话时区已是 +08 时会双重转换）。
