## 修复 BaseCheckInput 截图「没有任何预览」+ 辅助项接入同一套输入组件

### ① 根因：StrictMode 双调用把 objectURL 提前撤销（不是 CSS、不是粘贴逻辑）
- 真机 CDP 复现（dev 5174，`main.jsx` 开着 StrictMode）：粘贴后的 `<img>` **`naturalWidth = 0`**，`fetch(blob:…)` 直接 `Failed to fetch`；而"再选一张文件替换"却正常（`320×200` 能解码）
- 差别在于是否是 **CheckImage 的首次挂载**：StrictMode dev 下 effect 是「挂载 → 立刻卸载 → 再挂载」，原代码在卸载清理里同步 `URL.revokeObjectURL(useMemo 刚建的那个 url)` → URL 在真挂载前就作废 → 图永远出不来（换成"替换"时组件已挂着，清理的是旧 URL，所以看起来"换一张就好"）
- 上一轮的截图之所以看着正常，是"图片加载任务"与"passive effect 清理"的竞态，**偶然**跑赢了 —— 属于 flaky，不是真的好了

### ② 修法（`src/components/CheckImage.jsx`）
- `revokeLater(url)`：把 revoke 放进 `setTimeout(…, 0)`；`keepAlive(url)` 在重挂载时 clearTimeout 取消。StrictMode 的假卸载与重挂载在同一任务内完成，定时器来不及跑 → 真卸载才释放，假卸载被取消
- 验证：粘贴 / 文件选择 / 刷新后从 IndexedDB 恢复，三条路径 `naturalWidth` 均 > 0

### ③ 辅助项接入（`AuxiliaryCheckItem.jsx`）
- 备注 textarea（`{...register("note")}`）→ `BaseCheckInput`（`note` + `image` 受控）；时间输入保留 `register("time", { also:{ auto:false } })`
- 布局：实际时间单独一行，BaseCheckInput 全宽一行（截图工具条在 360px 侧栏里需要宽度）
- 配套（否则截图会静默丢）：
  - `checklistDraft.boxSnapshot()` 的 image 剥离**同时作用于 items 与 videoItems**（原先只处理 videoItems → 辅助项的 Blob 进 localStorage 会变成 `{}`）
