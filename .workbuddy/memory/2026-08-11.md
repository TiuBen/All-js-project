## 检查单模板规则引擎化（new-test.json / new-test2.json）

- 背景：用户要重构 cargo-checklist.json，把混乱的 timeLink 升级为可计算规则模型，结合 deepseek/chatgpt 两份思路（文件在 data/checklists/ 下，.md）。
- 两份思路核心共识：① 顶层加 variables（动态输入）+ parameters/lookupTables（机型参数表）；② timeLink 替换为可执行表达式树（AST）；③ desc 只展示、formula 负责计算；④ OR 逻辑用 min/max 明确；⑤ 参数按机型查表（lookup）。
- 产出（均通过 JSON 合法性 + 表达式树引用一致性校验 + 真实求值器验证）：
  1. `new-test.json`（v2）：variables + parameters(code/name/type/values) + formula 四型(anchor/offset/lookup/choice)。
  2. `new-test2.json`（v3，最终推荐）：融合两思路，formula 用完整 AST 五型——ref(target=event/var)/literal(value+unit)/lookup(param+key)/binary(operator)/function(min,max)+choice(condition分支)；节点加 eventId(E001~E014)+code(IN_POSITION 等英文码)+category(main/auxiliary)。
- 求值器关键坑：lookup 返回的整数分钟 + literal 的 unit 需统一转 timedelta，否则 datetime + int 报错（后端实现时同样要处理单位）。
- 关键数据：14 主事件、24 辅助项；4 参数(FUEL_TIME/UNLOAD_TIME/LOAD_TIME/CHOCK_TIME，均按机型)；7 变量(estimatedLanding/actualLanding/cobt/ctot/aircraftType/demandGroundPower/demandWater)。
