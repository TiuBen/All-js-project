# 检查项「文字 + 截图」输入框 —— 落地说明（2026-09-22）

## 一、需求来源与她的思路

`src/components/BaseCheckInput.md` 是另一段对话的记录。她的核心结论：

- 把裸 `textarea` 升级成一个独立输入框组件，支持 **文字 + `Ctrl+V` 粘贴截图 + 点选文件 + 缩略图 + 删除**
- 数据形状：每个检查项 `{ status, note, image }`，**每项只留 1 张图**（不做数组）
- 二进制用 **Blob** 存 IndexedDB（结构化克隆天然支持），**不转 Base64**、不做富文本、不需要图片服务器
- 保持现有 **逐项 Zustand 订阅**，`VideoPanel` 一行都不用改
- 最后收尾：图片上传后端留作下一步

她的判断都对，落地时补了 3 个她示例里没覆盖的点（见第四节）。

## 二、数据形状（定稿）

```js
// 每个视频监管项（也适用将来的主/辅助项）
{
  status: "abnormal",
  note: "现场发现 3 号机位人员未按要求站位，已通过广播纠正。",
  image: {
    id: "9a5d41de-…",              // 本地生成，React key + 落盘签名用
    name: "CAM-07-机坪全景.png",    // 截图粘贴时浏览器常给空名 → 兜底"截图.png"
    type: "image/png",
    size: 18432,
    blob: File,                    // 本地二进制（IndexedDB 直接存）
    url: "/api/uploads/xxx.png",   // 提交上传后才有；落库只存它
  }
}
```

`blob` 与 `url` **可只存其一**：本地新建只有 `blob`（离线可用），从服务端读回只有 `url`。
两者都没有（只有元信息）时缩略图显示「截图不可用」占位，不留破图。

## 三、数据流

```
截图软件 Ctrl+C
      │
      ▼
BaseCheckInput  ──paste/drop/文件选择──▶  image{ blob }
      │                                        │
      │ 受控 note / image                       ▼
      ▼                                 IndexedDB（结构化克隆，刷新/离线都在）
checklistDraft.memory.videoItems ──── 800ms 防抖落盘 ──▶  localStorage 草稿箱（只存元信息）
      │
      │ 点「提交」
      ▼
checklistStore.uploadDraftImages()  ──POST /api/checklists/uploads（原始二进制）──▶ data/uploads/xxx.png
      │                                                                              │
      │ image 换成 { ...meta, url }，内存同步（重复提交不重传）                        ▼
      ▼                                                                        静态托管
payload.videoSupervision ──▶ checklist_records.video_supervision（JSONB，只存 url）
      │
      ▼
详情页 VideoCheckView ──▶ 按 url 显示截图（换设备/事后复查都能看）
```

## 四、相对她的示例，我改了什么（3 处 + 2 处顺带）

| # | 她的写法 | 问题 | 落地做法 |
|---|---|---|---|
| 1 | `crypto.randomUUID()` | **只在安全上下文可用**；局域网 IP 打开（iPad 访问 `http://192.168.x.x`）时是 `undefined`，直接调用抛错 | `newImageId()` 带降级实现（时间戳 + 随机串） |
| 2 | objectURL 存在 `useState`、`useEffect` 里 create/revoke | 多一帧渲染；revoke 旧的与建新的之间 `<img>` 会拿到失效 URL **闪一下** | 抽成 `CheckImage`，`useMemo` 在渲染期算 URL、effect 只负责 revoke |
| 3 | `image: { file }` | `JSON.stringify(File)` → `{}`；落盘签名会因此**静默漏掉"换了一张图"** | 统一叫 `blob`；`contentSig()` 序列化时摘掉 blob（用 id/type/size 代表），localStorage 只写元信息 |
| 4 | —（未提） | `hasContent()` 只看 `memory.items` → **只填视频项（尤其只贴一张截图）时草稿永远不落盘**，刷新即丢 | 计入 `videoItems` 的 status/note/image |
| 5 | —（未提） | 提交时 `JSON.stringify` 会把 Blob 变 `{}`，截图**静默消失** | 提交前先上传，失败即中止落库（宁可不提交，也不丢证据） |

## 六、两个刻意的工程决定

1. **上传接口挂在 `/api` 前缀下**（`POST /api/checklists/uploads`，静态 `/api/uploads/xxx.png`）：
   开发环境的 vite 代理与线上 nginx 都只反代 `/api`，这样**两个环境都不用改代理配置**。
2. **不用 multer / FormData**：单文件、无字段，`express.raw` 足够，不引新依赖；
   请求体就是图片原始字节，服务端 `fs.writeFile` 直接落盘。

## 七、顺带修掉的既有 bug

详情页**从来没显示过任何视频监管项**（备注也看不到）：

- `ChecklistTreeView` 按 `template.schema[].videoSupervision` 把视频项挂到节点下，但模板数据里
  这个字段**全为空**（实测 5 个模板 `schema` 共 53 个节点、videoSupervision 条目 0 个）；
  视频监管在模板里是**独立一份平面数据**（`TemplateJson/xxxVideoFocus.js` 的 `groups[]`），
  与主监控节点**没有从属关系** → 旧的 `VideoList` 永远渲染空列表。
- 修法：新增 `VideoCheckView` 独立面板（与编辑器第三列同一份数据源、同一套 category 映射），
  顶部统计把视频项一起计入；删掉已成死代码的 `VideoList.jsx`。

## 九、遗留 / 可选

- **主监控、辅助项还没接入** `BaseCheckInput`（它们的备注目前是裸 textarea，布局也不一样）。
  组件是通用的，接一行即可，但会改变现有行内布局，需要你确认要不要动。
- **孤儿图片**：删除检查单记录不会删 `data/uploads` 里的文件（证据类附件刻意不做级联删除），
  需要时再加一个清理脚本/定时任务。
- 详情页 24h 锁定后仍可看截图；若以后要支持"锁定后仍允许补截图"，需要后端放开规则。
- 图片体积上限 8MB（前后端一致）；超过时前端常驻提示并忽略该图。
