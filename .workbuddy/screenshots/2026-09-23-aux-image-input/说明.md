## 预览为什么会失效

`main.jsx` 开着 React `StrictMode`。dev 下每个 effect 都会走一遍「挂载 → 立刻卸载 → 再挂载」。

原代码在**卸载清理里同步撤销** objectURL：

```js
useEffect(() => () => { if (localUrl) URL.revokeObjectURL(localUrl) }, [localUrl])
```

于是那张 `blob:` URL 在**真正的挂载之前就被作废**了，`<img>` 拿到一个失效地址 —— 实测 `naturalWidth = 0`、`fetch(blob:…)` 直接失败。

症状很有迷惑性：**只有「组件第一次出现」的那张图会坏**。再换一张时 `CheckImage` 已经挂着，清理的是旧 URL，所以看起来"换一张就好了"；刷新页面后重新挂载 → 又坏。

修法（`CheckImage.jsx`）：把释放推迟一拍，重挂载时取消。

```js
const pendingRevoke = new Map()
function keepAlive(url) { /* clearTimeout 取消待释放 */ }
function revokeLater(url) { setTimeout(() => URL.revokeObjectURL(url), 0) }
```

StrictMode 的"假卸载 + 重挂载"发生在同一个任务里，`setTimeout` 还来不及跑就被取消；真卸载则照常释放，不漏内存。

## 辅助项接入的连带改动

截图二进制作 Blob 存 IndexedDB、提交时才上传 —— 辅助项的截图存进 `items['aux-<uuid>'].image`，因此三处必须一起改，否则图会**静默消失**：

| 位置 | 改动 |
|---|---|
| `checklistDraft.boxSnapshot()` | 剥 image 二进制时**同时处理 items 与 videoItems**（原先只看 videoItems，辅助项的 Blob 写进 localStorage 会变成 `{}`） |
| `checklistStore.uploadDraftImages()` | 返回 `{ items, videoItems }`，两份都扫、都把内存里的 blob 换成 url |
| 查看页 `AuxiliaryList` | 用 `CheckImage` 展示辅助项截图（之前只显示备注文字） |

另外顺手修掉 `AuxiliaryList` 里 `{aItem.note}是` 的多余字。
